# Meta Education — платформа подготовки к ЕГЭ

Для VPS с Docker и Yandex Object Storage: [инструкция по развёртыванию](deploy/VPS.md). Общий Nginx Proxy Manager обслуживает домены и автоматически продлевает сертификаты Let's Encrypt. Приложение доступно ему по адресу `meta-education:3000` в сети `proxy`; Postgres остаётся в отдельной внутренней сети. Push в `main` запускает тесты и сборку Docker в GitHub Actions, затем готовый образ передаётся по SSH и запускается на VPS без сборки. [Переход с установленного Nginx и подключение других сайтов](deploy/PROXY.md).

Полноценный локальный MVP на Next.js App Router, React и TypeScript. Интерфейс на русском языке, четыре роли: ученик, преподаватель, менеджер и администратор. Шрифты хранятся локально. GSAP-анимации учитывают системную настройку уменьшения движения.

## Запуск

Требуется Node.js 22+ и pnpm.

```sh
pnpm install
pnpm dev
```

Откройте [localhost:3000](http://localhost:3000). Без внешних сервисов dev-сервер запускает демонстрацию с сохранением данных в `.data/database.json`, файлов — в `.data/uploads`. Внизу страницы можно переключаться между четырьмя ролями. В деморежиме используются только вымышленные данные.

В текущем рабочем каталоге уже создан `.env.local` с настройками подключений. Для повторного запуска локальных Docker-сервисов выполните `docker compose --env-file .env.local up -d`. Этот файл исключён из Git; заданные в нём параметры сохраняют существующую базу после переименования. Чтобы попробовать автономный режим, используйте настройки `.env.example` с пустыми `DATABASE_URL` и `S3_BUCKET`.

Демонстрационные аккаунты в новой демобазе (в существующей базе остаются прежние email и пароли):

| Роль               | Email                       | Пароль             |
| ------------------ | --------------------------- | ------------------ |
| Преподаватель      | teacher@meta-education.demo | MetaEducation2026! |
| Менеджер           | manager@meta-education.demo | MetaEducation2026! |
| Администратор      | admin@meta-education.demo   | MetaEducation2026! |
| Ученик, Александра | sasha@meta-education.demo   | MetaEducation2026! |
| Ученик, Михаил     | misha@meta-education.demo   | MetaEducation2026! |

В production демонстрация выключена по умолчанию. Чтобы явно запустить её после сборки, задайте `DEMO_MODE=true` перед `pnpm start`. **Не размещайте реальные данные в демонстрационном режиме:** его переключатель намеренно позволяет входить без пароля.

## Что работает

- Обзор: показатели из фактических работ, график результата, очередь проверки, ближайшее занятие и календарь недели.
- Вход по email и паролю; одноразовые приглашения на 7 дней с ролью и учебными пространствами; регистрация ученика с возможностью добавления в группу.
- Раздел «Доступ и приглашения»: менеджер приглашает учеников и преподавателей, администратор также приглашает менеджеров; оба управляют доступом учеников и преподавателей к математике и проектированию.
- Конструктор заданий: условия, предмет, дедлайн, максимальный балл, файлы и выбор учеников по одному или группами.
- Задания: поиск, фильтры, сортировка, просроченные работы, архивирование и восстановление.
- Сдача текстовых ответов и JPG/PNG/PDF до 20 МБ на файл; загрузка перетаскиванием.
- Очередь работ, по умолчанию от старых к новым; просмотр ответов, изображений и PDF; баллы, рецензия и проверенные файлы.
- Ученики и их ближайшие занятия, создание и редактирование групп, недельное расписание.
- Журнал «Ученики × Задания», переход к работе по ячейке, выгрузка CSV.
- Профиль, изменение имени/email/пароля, поиск по заданиям и ученикам, уведомления о работах на проверке.
- Адаптивный интерфейс, прокрутка широких таблиц внутри контейнера, клавиатурная навигация и удержание фокуса в модальных окнах.

Расписание хранит даты в UTC и показывает их в часовом поясе браузера. Ссылку на видеоурок преподаватель добавляет в поле места занятия; интеграция с внешним календарём не требуется.

## Рабочая тетрадь и помощь ИИ

Переключатель вверху левой панели открывает два пространства: «Математика» и «Проектирование». Все шесть блоков рабочей тетради находятся в «Проектировании»; задания, расписание и учебный обзор остаются в «Математике». Выбранное пространство сохраняется в адресе страницы, в том числе при открытии настроек и использовании кнопок браузера «Назад»/«Вперёд». Новые ссылки имеют вид `/#design/workbook/6`; старые `/#workbook/6` также открывают соответствующий блок в «Проектировании». Ответы и права доступа не меняются.

Блок 6 «Журнал неудач» содержит пошаговую форму: дата и событие, ожидание и результат, категория, разбор и конкретный вывод с необязательным следующим шагом. У каждой из трёх категорий есть пояснение, пример и свой вопрос. Ответы разных категорий сохраняются при пересмотре классификации. История показывается таблицей с фильтром по категории, полным просмотром и редактированием. Каждая запись сохраняется отдельно с проверкой версии, чтобы устаревшая вкладка не затёрла изменения. Записи доступны только их автору.

В кабинете ученика раздел «Рабочая тетрадь» открывается по клику. Блок 1 «Где я сейчас?» сохраняет оценки четырёх сфер, пояснения и приоритет; сохранённый результат можно скачать в PDF с датой заполнения. Блок 2 «Компас» содержит пространства «Работа» и «Жизнь», счётчики слов с ориентиром 250 и три вопроса о согласованности. Черновики можно сохранять до завершения всех ответов. Экспорт в PDF включает все ответы и дату сохранения; длинные тексты переносятся на следующие страницы. Результаты каждого блока доступны только их автору.

Блок 3 «Дневник хорошего времени» хранит до 21 карточки с уникальными датами. В каждой — одно или несколько занятий (до 50), вовлечённость 0–10, энергия −5…+5 и отметка «В потоке». Полукруглые шкалы поддерживают мышь, касание, стрелки клавиатуры и кнопки изменения значения. Нулевая оценка отличается от незаполненной. После семи сохранённых дней доступна рефлексия AEIOU: Действия, Окружение, Взаимодействия, Предметы, Люди. Можно сохранять частичные ответы и дополнять их позже. Изменение дневников помечает сохранённую рефлексию как требующую пересмотра; удаление дней не удаляет выводы.

Блок 5 «Планы Одиссеи» содержит три независимых сценария на пять лет и таблицу сравнения. События пяти категорий переносятся между годами перетаскиванием или выбором года; поддерживаются отметки предположений и рисунки мышью или пальцем. Черновики сохраняются на любом этапе. Для завершения сценария нужны название ровно из шести слов, два-три вопроса, хотя бы одно событие и четыре оценки 0–10. У каждой оценки есть необязательное пояснение. Возле согласованности показываются только собственные сохранённые ответы из «Компаса». В каждом сценарии доступно до 40 событий; рисунок хранится как проверенные координаты штрихов вместе с планом. Сохранение защищено от перезаписи из устаревшей вкладки.

Чтобы включить помощь DeepSeek, задайте на сервере `DEEPSEEK_API_KEY` и `DEEPSEEK_MODEL=deepseek-flash`: локально в `.env.local`, на VPS в `.env.production`. Перезапустите приложение после изменения переменных. В `compose.production.yaml` они передаются контейнеру; ключ не должен иметь префикс `NEXT_PUBLIC_` и не попадает в браузер. Без ключа ручное заполнение и сохранение работают, а помощь ИИ недоступна.

Запрос отправляется только по кнопке ученика: для «Компаса» он содержит тексты «Работа» и «Жизнь», для ДХВ — сохранённые даты, описания занятий, оценки и отметки потока. Используется обычный режим без рассуждения и структурированный JSON-ответ, который проверяется на сервере. Подсказки показываются отдельно и добавляются в ответ только по выбору пользователя. Изменение исходных записей делает предыдущие подсказки неактуальными. Таймаут запроса: 60 секунд; общее ограничение обоих блоков: 20 запросов в час на ученика, минимум 10 секунд между запросами. В журнал квоты записываются только идентификатор ученика, количество и время запросов.

Документация интеграции: [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) и [JSON Output](https://api-docs.deepseek.com/guides/json_mode/). Имя `deepseek-chat` снято с поддержки; актуальная модель для этой интеграции — `deepseek-flash`.

## Postgres и S3

Скопируйте `.env.example` в `.env.local`, задайте:

```dotenv
DEMO_MODE=false
APP_URL=https://your-domain.example
DATABASE_URL=postgresql://user:password@host:5432/meta_education
ADMIN_NAME=Имя администратора
ADMIN_EMAIL=teacher@example.ru
ADMIN_PASSWORD=Замените-на-уникальный-пароль-от-12-символов
S3_ENDPOINT=https://storage.yandexcloud.net
S3_REGION=ru-central1
S3_BUCKET=your-private-bucket
S3_ACCESS_KEY_ID=your-access-key
S3_SECRET_ACCESS_KEY=your-secret-key
S3_FORCE_PATH_STYLE=false
```

Бакет должен быть закрытым. Для AWS можно не задавать `S3_ENDPOINT`; для Selectel укажите endpoint и регион своего проекта. Сервисному аккаунту нужны операции записи и чтения объектов этого бакета. Публичный доступ и настройка CORS бакета не нужны: загрузки идут через сервер, скачивания — по подписанному URL.

При первом запросе таблицы и единственный администратор создаются автоматически из `ADMIN_*` (на VPS — из `.env.production`). При обновлении старой базы прежний преподаватель с email из `ADMIN_EMAIL` получает роль администратора; его ID, пароль, сессии и учебные данные сохраняются. Эта миграция применяется только к старым аккаунтам без списка пространств. Новые приглашения и изменение email не повышают роль до администратора. Пароль и имя из окружения применяются только при создании пустой базы.

Ученик работает в доступных ему пространствах. Преподаватель сохраняет учебные функции, но не создаёт приглашения. Менеджер управляет приглашениями и доступом, без просмотра решений, оценивания или работы с тетрадями. Администратор сочетает права преподавателя и менеджера. Создать приглашение администратора через интерфейс или API нельзя.

У существующих учеников и преподавателей сохраняется доступ к обоим пространствам. Новым пользователям пространства назначаются при приглашении. Закрытие доступа действует на каждый последующий запрос, в том числе в существующей сессии, на PDF и вложения; сохранённые работы не удаляются. Интерфейс обновляет права при возврате во вкладку. Доступ можно закрыть ко всем пространствам, сохранив вход в аккаунт и настройки профиля. Рабочие тетради остаются личными: их содержимое доступно только ученику с открытым проектированием.

Для ручной инициализации с Node.js, поддерживающим `--env-file`:

```sh
node --env-file=.env.local --import tsx scripts/init-db.ts
pnpm build
pnpm start
```

Для реальных пользователей нужны домен с HTTPS и указанный `APP_URL`. Production-cookie имеет флаги `HttpOnly`, `Secure`, `SameSite=Lax`. Локальный HTTP с `DEMO_MODE=false` не предназначен для входа в production-cookie.

### Локальные внешние сервисы

В репозитории есть `compose.yaml` для Postgres 17 и MinIO. Порты привязаны только к localhost; приведённые пароли предназначены для локальной разработки.

```sh
docker compose --env-file .env.local up -d
```

- Postgres: `postgresql://meta_education:meta-education-local-dev@127.0.0.1:35432/meta_education`
- S3 API: [127.0.0.1:39000](http://127.0.0.1:39000)
- MinIO Console: [127.0.0.1:39001](http://127.0.0.1:39001), логин `meta-education-local`, пароль `meta-education-local-dev-storage`.

Для просмотра демонстрации с этими сервисами установите `DEMO_MODE=true`, укажите локальные `DATABASE_URL`, `S3_ENDPOINT`, `S3_REGION=us-east-1`, `S3_FORCE_PATH_STYLE=true`, ключи MinIO и предварительно созданный закрытый бакет в `S3_BUCKET`.

`node --env-file=.env.local --import tsx scripts/setup-local.ts` создаёт локальную БД и закрытый бакет. Скрипт принимает только адреса localhost и демонстрационный режим. Если файловое демо уже использовалось, `--import-demo` перенесёт отсутствующие записи, не перезаписывая существующие; импорт локальных файлов требует отдельного переноса и намеренно не выполняется автоматически.

`docker compose --env-file .env.local stop` остановит сервисы, сохранив данные. Есть также Dockerfile со сборкой Next.js standalone; рабочие переменные окружения передаются контейнеру при запуске, не встраиваются в образ.

Значения выше относятся к новой установке. Для существующих локальных volumes используйте значения из своего `.env.local`: `COMPOSE_PROJECT_NAME`, `POSTGRES_USER`, `POSTGRES_DB`, `LOCAL_POSTGRES_PASSWORD`, `LOCAL_MINIO_USER`, `LOCAL_MINIO_PASSWORD`. Прежний префикс SQL-таблиц сохранён для совместимости с данными. [Обновление уже развёрнутой платформы после переименования](deploy/VPS.md#переход-с-прежнего-названия-точка).

## Проверки

```sh
pnpm typecheck
pnpm test
pnpm build
```

`pnpm test` запускает 16 проверок: пароли и права на файлы, приглашение, регистрация, назначение, загрузка, конкурентная сдача, проверка баллов, публикация рецензии, группы/расписание, выход и ограничение попыток входа, включая подмену IP перед Nginx Proxy Manager. HTTP-тест поднимает отдельный сервер на порту 3100 с отдельными данными; основной кабинет не изменяется.

Тот же сценарий можно выполнить на реальных Postgres и MinIO после `docker compose --env-file .env.local up -d`. В PowerShell:

```powershell
$env:TEST_DATABASE_URL = 'postgresql://meta_education:meta-education-local-dev@127.0.0.1:35432/meta_education'
$env:TEST_S3_ENDPOINT = 'http://127.0.0.1:39000'
pnpm test
```

Тест создаёт изолированную схему Postgres и временный закрытый бакет, проверяет подписанные URL, запрет анонимного доступа, затем удаляет только собственные тестовые ресурсы. Локальные файловые тесты сохраняют свои данные в `.data/test-*` для диагностики.

## Архитектура и границы MVP

- `app/api/[...path]/route.ts` — HTTP API App Router; `lib/api.ts` — серверная валидация и проверка ролей.
- `lib/db.ts` — транзакционный repository: отдельная Postgres-таблица для каждой сущности, содержимое записи хранится в JSONB. Проверка и запись проходят под advisory lock, защищающим от одновременного использования приглашения, повторной сдачи и потери изменений.
- `lib/security.ts` — scrypt с индивидуальной солью; случайные сессии и приглашения, в базе хранятся их SHA-256 хеши. Авторизация файла проверяется при каждом запросе; S3 URL действует 60 секунд.
- `lib/storage.ts` — S3 SDK; в демонстрации без S3 используется локальное закрытое хранилище за API.
- `components/` — интерфейс кабинетов и форм. Основные разделы доступны по URL-фрагменту, например `/#assignments` и `/#gradebook`.

Это реализация для одного преподавателя и небольшого учебного пространства. Repository читает набор сущностей целиком и сериализует изменения; для больших школ понадобятся нормализованные связи, индексы и пагинация. Файлы загружаются последовательно с ограничением 20 МБ, затем открываются отдельно от списков. Сканирование вредоносного содержимого, антивирус, автоматическое распознавание ответов, email-рассылки и восстановление пароля по email в текущий объём не входят. Неиспользованные загруженные вложения не удаляются автоматически; при большом обороте потребуется фоновая очистка.

Для работы нескольких экземпляров приложения используйте Postgres и S3. Файловый режим предназначен для одного локального процесса. `TRUST_PROXY=true` рассчитан на один доверенный прокси перед приложением: он добавляет адрес клиента в конец `X-Forwarded-For` или полностью перезаписывает заголовок. Так работают Nginx Proxy Manager и прежний шаблон Nginx. Это добавляет ограничение входов по IP к ограничению по email. В общую сеть `proxy` подключайте только доверенные приложения; базы данных оставляйте в сетях своих проектов.

Реализация использует официальные API [Next.js Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers) и [cookies](https://nextjs.org/docs/app/api-reference/functions/cookies).
